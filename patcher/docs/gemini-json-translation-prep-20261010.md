## 프롬프트

사용자가 품질이 좋다고 확인한 JSON AI Translator의 **실제 시스템 프롬프트 파일은 로컬 검색에서 확정하지 못했다.** 따라서 동일 프롬프트를 입수하거나 도구 설정에서 확인할 때는 이를 우선 사용하고, 임시 `00_system_prompt_draft.md`의 Fallout 세계관/고유명사/제어문자 보존 규칙을 추가한다.

프롬프트의 핵심 검수 규칙:
- 뉴베가스·Fallout 3·TTW 고유명사 통일과 원문 문맥 보존
- JSON 키 및 순서와 항목 수 불변
- Script·INI 식별자와 `%s`, `%d`, `{variable}`, `<br>`, 이스케이프 문자의 원형 보존
- 한국어 문체와 주어/존대 구별, 성별·화자 관계 추측 금지
- 긴 책/대사와 짧은 UI 레이블을 동일한 스타일로 처리하지 않음

## API를 호출하는 프로그램/번역 도구에 연결할 때

1. 프로젝트별 입력 JSON을 선택하고 사용자 지정 프롬프트에 위 번역 규칙을 반영한다.
2. JSON의 **문자열 값만 번역**하고 키는 원본 그대로 둔다.
3. 번역 결과물은 `results/project_N/<입력파일명>.translated.json`에 저장한다. 원본 입력파일은 수정하지 않는다.
4. `python tools/check_gemini_json_results.py`를 실행한다.
5. QA는 키·순서·건수·원문 해시·토큰·개행·빈 번역·한글 미탐지를 확인하고 `04_결과_검수`에 검수용 CSV를 작성한다. 기존 QA 보고서가 있으면 번호가 붙은 새 폴더에 추가해 덮어쓰지 않는다.
6. **QA 통과 후보조차 바로 패쳐에 적용하지 않고** 세계관·고유명사·퀘스트·화자·조건문을 별도 검수한다. 한국어 승인 CSV를 새 SST 매핑으로 변환한 후 네이티브 적용/재로드 및 게임 검증을 통과해야 한다.

프로젝트 키 4개는 소유자 환경에서 안전하게 관리한다. 코드/JSON 작업물·Git 커밋·로그에 키를 포함하지 않는다. 프로젝트별 서비스 약관과 할당량, 오류 시 백오프를 준수한다.

## 안전

- 원본 게임/모드 ESP·ESM, 정식 번역 메모리 및 게임 문장 원문은 **로컬에만 유지한다**.
- 저장소에는 **JSON 배치 생성 도구와 검사 코드, 메타데이터 보고서만** 올린다.
- 아직 사용자 확정 프롬프트와 실제 Gemini 연결이 없으므로 **번역 생성 진행률은 0**이며 정식 릴리즈 대상이 아니다.
- 다수의 번역 문구가 실제 게임에 표시되지 않을 수도 있다. 실사용 문맥 검수는 후속 단계다.

## 2026-10-10: 4개 독립 API 키 복구

기존 로컬 API 번역기 두 인스턴스에는 키 2개만 설정되어 있었지만, 과거 Fallout London 작업의 지정 키 파일에서 총 4개의 서로 다른 키(기존 AIza 2개 및 신규 AQ. 2개)를 확인했다. 신규 추가 2개에 대해 `gemini-3.1-flash-lite`를 사용하는 독립 최소 요청 테스트가 모두 성공했다.

`run_gemini_nuclear_unattended.py`는 기존 설정의 2개 키와 `.local/gemini_credentials_sources.json`의 **비밀값이 아닌 파일 경로 목록**에 지정된 키 파일에서 나머지 키를 로드한다. API 키 값은 출력, 커밋, 문서화하거나 새 파일로 복사하지 않는다. `.local` 설정 파일은 Git 추적에서 제외된다.

4개 프로젝트에 각각 하나의 키를 배정하는 재개형 실행기를 다시 시작했고, 로컬 상태 보고에서 `configured_key_slots=4`, `lane_batches=[198,223,209,229]`, 네 키의 진행 엔트리가 모두 확인됐다. 기존 번역 결과를 보존하며 완료 파일은 다시 API에 요청하지 않는다. 프로젝트 키당 일일 최대 220회 요청으로 제한하고, 한도 도달 시 다음 날까지 중지하는 정책은 유지한다.

이 기록은 **번역 완료**를 뜻하지 않는다. 원문/번역 데이터, 키 소스 파일은 로컬에만 남으며, 번역 품질 및 실제 게임 적용은 별도 검수 대상이다.
