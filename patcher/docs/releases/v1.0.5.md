# v1.0.5 개발 변경 사항

- 기존 한국어 패치가 입력 모드에 남아 있어도 같은 레코드·필드·경로의 최신 한국어 번역을 재사용합니다.
- 기존 버전의 `TranslationData`를 가진 배포 담당자는 `tools/merge_previous_catalogs.py`로 과거 번역 문자열을 새 카탈로그에 포함할 수 있습니다. 이렇게 연결된 이전 번역은 새 문구로 갱신됩니다. 이력이 없다면 추측해서 이전 한글을 변경하지 않고 대응 실패 내역에 남깁니다.
- `PERK`를 포함한 플러그인 매핑에서 새 영문 원문이 기존 카탈로그와 달라지면 해당 레코드/필드 경로를 확인할 수 있도록 대응 실패 원인을 분류합니다.
- 별도 Output과 결과 보고서의 출력을 유지합니다. GUI는 동일한 이름의 출력물이 이미 있으면 고유 이름으로 새 폴더를 만듭니다.
- Nuclear Sunset #11의 NVSE 런타임 설명문을 처리합니다. `Tag Perk Description Adjustment`, `SSS - Sweets Simple Settings`의 `gr_TagPerkDescriptionSetter.txt`는 명시된 `SetFormDescription Tag` 영어 설명문만 번역합니다. `Bullet Time - Perk Consistency Patch`의 `gr_BulletTimePerkDesc.txt`는 `GetFormDescription` 결과가 ASCII일 때만 기존 3개의 정규식 치환·재설정을 실행하게 안전 조건을 씌웁니다. 두 Tag 모드의 물리 폴더 모두에 별도 Output을 만듭니다.

## #11 특전 번역 검수 현황

실제 설치된 테스트 Output의 PERK 번역이 한국어로 들어간 사실을 확인했으며, 게임 시작 시 실행되는 NVSE 스크립트가 내용을 다시 바꾸는 별도 원인을 확인했습니다. Tag! 및 Bullet Time의 원본 스크립트 바이트를 확보해 해당 런타임 동작을 수정했습니다. 이는 비파괴 출력/소스 회귀 검증을 완료한 상태이며 인게임 문구 표시 검증은 아직 필요합니다. Fast Metabolism의 추가 영어 문장은 `Sweet Consumables.esp`의 **컴파일된 SCPT/SCDA**가 `%z Alcohol will also reduce your radiation twice as quickly.`를 추가하는 문제로, 별도의 컴파일된 스크립트 대책이 필요합니다. SCTX 원문만 교체하면 SCDA 동작과 불일치하므로 그렇게 처리하지 않습니다.

## 검증

`python -m unittest discover -s tests`로 소스 단계 회귀 검사. 새 배포본의 게임 실행 검증과 이전 버전 카탈로그의 실제 대응 검사는 배포 전 필요합니다.
